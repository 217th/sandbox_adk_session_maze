## ДОПОЛНЕНИЕ К SYSTEM DESIGN DOCUMENT (SDD)

### Session Flash (Одноразовые Атрибуты)

Дополнительный слой данных в сессии, реализующий паттерн "Read-Once" (прочтение с уничтожением).

**Назначение:** Передача контекстных сообщений, реакций на ошибки или уведомлений, которые актуальны исключительно для **следующего** ответа агента и не должны сохраняться в долгосрочном `State` или замусоривать `Events`.

**Структура данных:**
В объекте сессии выделяется специальный ключ (например, `_flash_buffer`), содержащий очередь сообщений.

```json
{
  "_flash_buffer": {
    "notifications": [], // List<String>
    "errors": []         // List<String>
  }
}
```

### Логика Flash Attributes

Кодирующий агент должен дополнительно реализовать методы для работы с Flash-памятью в `SessionManager`.

**1. Запись (Write / Push):**

  * Метод: `add_flash(category, message)`
  * Поведение: Добавляет сообщение в соответствующий список внутри `_flash_buffer`.
  * *Важно:* Данные сохраняются в сессии до момента их явного извлечения.

**2. Чтение (Consume / Pop):**

  * Метод: `consume_flash(category)`
  * Поведение:
    1.  Возвращает текущий список сообщений для категории.
    2.  **Немедленно очищает** этот список в сессии (удаляет данные).
    3.  Если сообщений нет, возвращает пустой список.

**3. Сценарий использования (Пример "Лабиринт"):**

  * **Событие:** Агент вычисляет ход и обнаруживает столкновение со стеной.
  * **Действие:** Вызывается `session.flash.add("notifications", "Удар был болезненным!")`.
  * **Генерация ответа (Текущий ход):** Шаблон ответа проверяет Flash. Видит сообщение -\> добавляет его к ответу.
      * *Вывод:* "Стена. Удар был болезненным\!"
  * **Следующий ход:** Пользователь вводит "Где я?".
  * **Генерация ответа (Следующий ход):** Шаблон ответа проверяет Flash. Список пуст (был очищен в прошлом ходе).
      * *Вывод:* "Вы находитесь в (0,0)." (Сообщение про боль исчезло).

### Дополнительные Требования к Тестированию (Flash)

Кодирующий агент обязан добавить следующие тест-кейсы в набор автоматических тестов:

**Тест-кейс: Эфемерность Flash-данных**

  * **Шаг 1 (Setup):** Добавить сообщение "Test Msg" во Flash.
  * **Шаг 2 (Verify):** Проверить, что сообщение присутствует в сессии.
  * **Шаг 3 (Action):** Вызвать метод `consume_flash()`.
  * **Шаг 4 (Assert):** Убедиться, что метод вернул "Test Msg".
  * **Шаг 5 (Assert Persistence):** Проверить состояние сессии снова. Убедиться, что `_flash_buffer` пуст или ключа не существует.

**Тест-кейс: Изоляция между ходами**

  * **Шаг 1:** Симулировать ход 1, где генерируется Flash-сообщение.
  * **Шаг 2:** Симулировать генерацию ответа (чтение Flash).
  * **Шаг 3:** Симулировать ход 2.
  * **Шаг 4:** Убедиться, что в контексте хода 2 Flash-сообщения из хода 1 отсутствуют.
