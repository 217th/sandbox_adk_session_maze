# System Design Document (SDD): ADK Maze Agent Session Demo

## 1\. Введение и Цели

Целью данного проекта является создание учебного агента на базе Google ADK для демонстрации управления контекстом сессии в рамках одного диалога (Turn-based conversation).

**Ключевая задача:** Реализовать и продемонстрировать различие между двумя типами хранения данных в сессии:

1.  **State (Состояние):** Изменяемые данные (Mutable), отражающие текущий статус системы.
2.  **Events (События):** Неизменяемый журнал (Append-only), отражающий историю действий пользователя.

## 2\. Сценарий Использования (Use Case)

**Название:** "Агент Лабиринта" (Maze Agent).
**Суть:** Пользователь перемещается по виртуальной сетке 3x3.
**Цель пользователя:** Добраться из точки (0,0) в точку (2,2).

### 2.1 Карта Лабиринта (Grid 3x3)

  * **Координаты:** (x, y), где x=0..2, y=0..2.
  * **Старт:** (0, 0).
  * **Финиш:** (2, 2).
  * **Стены (непроходимые зоны):** (1, 0) и (1, 1).

## 3\. Модель Данных Сессии

Кодирующий агент обязан реализовать следующие структуры данных внутри объекта `session` (или `context`), предоставляемого ADK.

### 3.1 Session State (Хранилище Состояния)

Представляет собой *snapshot* текущего положения. Перезаписывается при каждом успешном действии.

```json
{
  "player_position": {
    "x": 0, // Integer: 0-2
    "y": 0  // Integer: 0-2
  },
  "game_status": "active" // Enum: "active", "won"
}
```

### 3.2 Session Events (Хранилище Событий)

Представляет собой *log* действий. Новые записи добавляются в конец списка. Данные не удаляются и не изменяются.

```json
[
  {
    "timestamp": "ISO-8601 String",
    "action_type": "MOVE_ATTEMPT", // Enum: MOVE_ATTEMPT, LOOK, SYSTEM_MSG
    "parameters": {
      "direction": "north", // optional
      "result": "success"   // Enum: "success", "blocked", "out_of_bounds"
    }
  }
  // ... последующие события
]
```

## 4\. Функциональные Требования (Логика Агента)

Агент должен обрабатывать входящие текстовые команды в цикле.

### 4.1 Обработка Ввода (Input Processing)

Поддерживаемые команды:

  * `go north`, `go south`, `go east`, `go west` (перемещение).
  * `look` (осмотр текущей позиции).
  * `history` (отладочная команда: вывести сырой список Events).

### 4.2 Логика обновления (Write Logic)

1.  **При попытке хода:**
      * Агент вычисляет целевую координату на основе *Current State*.
      * Проверяет валидность хода (границы карты и стены).
      * **Если ход успешен:**
          * Обновляет `player_position` в *Session State*.
          * Добавляет запись `{type: "MOVE_ATTEMPT", result: "success"}` в *Session Events*.
      * **Если ход невозможен (стена/граница):**
          * *Session State* **НЕ** меняется.
          * Добавляет запись `{type: "MOVE_ATTEMPT", result: "blocked"}` в *Session Events*.

### 4.3 Логика чтения и реакции (Read Logic)

Это критическая секция для демонстрации "ощущения" данных.

1.  **Стандартная реакция:** Агент сообщает текущее состояние (State).
      * *Пример:* "Вы находитесь в (0,0). Путь на восток заблокирован."
2.  **Реакция на основе Событий (Events Pattern Matching):**
      * Агент должен анализировать список *Events* перед ответом.
      * **Условие "Упрямство":** Если последние 3 события — это `MOVE_ATTEMPT` с результатом `blocked` или `out_of_bounds`.
      * **Действие:** Агент меняет тон ответа на саркастический или подсказывающий.
      * *Пример:* "Я вижу, вы уже 3 раза ударились в стену. Может, попробуете другое направление?"

## 5\. Архитектура и Интерфейсы (Python / ADK)

Кодирующий агент должен использовать структуру, совместимую с ADK Runner.

### 5.1 Компоненты

1.  **`MazeEngine`**: Класс, инкапсулирующий правила игры (проверка границ, стен). Не хранит состояние, только вычисляет логику.
2.  **`SessionManager`**: Обертка над API сессии ADK.
      * Метод `get_state()`
      * Метод `update_state(new_data)`
      * Метод `add_event(event_data)`
      * Метод `get_recent_events(count)`
3.  **`AgentHandler`**: Основная функция обработки хода (process turn).

### 5.2 Псевдокод потока (Flow)

```python
def process_user_turn(user_input, session):
    # 1. Извлечение данных
    current_pos = session.state.get('player_position')
    
    # 2. Логика игры
    move_result = MazeEngine.calculate_move(current_pos, user_input)
    
    # 3. Запись в сессию
    if move_result.success:
        session.state.set('player_position', move_result.new_pos)
    
    session.events.add({
        'type': 'MOVE_ATTEMPT', 
        'direction': user_input, 
        'result': move_result.status
    })
    
    # 4. Генерация ответа (чтение событий)
    recent_failures = count_consecutive_failures(session.events.get_all())
    
    if recent_failures >= 3:
        return "Кажется, вы застряли. Попробуйте осмотреться."
    else:
        return f"Вы переместились. Текущая позиция: {session.state.get('player_position')}"
```

## 6\. Требования к Тестированию (Automated Testing)

Кодирующий агент обязан предоставить набор тестов (например, `pytest`), проверяющих целостность сессии.

**Тест-кейс 1: Сохранение Состояния (State Persistence)**

  * **Действие:** Сделать шаг "South" из (0,0).
  * **Ожидание:** В следующем ходе `session.state.player_position` равно `(0, 1)`.

**Тест-кейс 2: Неизменяемость при ошибке**

  * **Действие:** Попытаться пройти сквозь стену.
  * **Ожидание:** `session.state.player_position` не изменилось.

**Тест-кейс 3: Накопление событий (Event Accumulation)**

  * **Действие:** Сделать 3 ошибочных хода.
  * **Ожидание:** В `session.events` содержится 3 записи с `result: blocked`.
  * **Ожидание:** Агент возвращает специальное сообщение (срабатывание логики на основе истории событий).
